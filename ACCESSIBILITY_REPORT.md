# Accessibility review

The browser accessibility tree exposed the Arabic homepage skip link, labeled main and footer navigation, language switch, headings, CTA links, and descriptive Arabic text for the studio artwork. One H1 and one main landmark were observed on each of 18 localized desktop pages. Document direction, localized titles, and the absence of desktop horizontal scrolling were checked on all pages. The Arabic homepage layout was inspected visually; the wordmark read left-to-right within the Arabic interface. A missing space between hero words was corrected in the heading markup.

Semantic inspection does not establish all contrast, zoom/reflow, announcement, focus or touch-target requirements. The prepared suite includes narrow widths, 200% text, menu keyboard opening/closing and optional axe-core checks. GitHub Actions exercised all 18 pages in three engines. All 54 desktop axe scans passed the selected WCAG tags. A separate 200% text test failed on all 18 pages in all engines. Firefox also found regular viewport overflow; see QA_RESULTS.md. These are release blockers until the corrected revision is retested. Verify live form errors, page and drawer focus, high text scaling, and native Arabic/English screen-reader navigation on target devices before making a WCAG 2.2 AA claim.

In the fixed revision, 200% text at 390 px passed for all 18 public routes across Chromium, Firefox and WebKit. The 320–1920 px viewport matrix and both native disclosure keyboard checks passed each engine. The 54 desktop axe scans again reported no violations for the tested tags. Manual testing on native assistive technology and physical devices remains pending. [Regression run](https://github.com/ha7n-bot/just-a-space/actions/runs/45933864993)
